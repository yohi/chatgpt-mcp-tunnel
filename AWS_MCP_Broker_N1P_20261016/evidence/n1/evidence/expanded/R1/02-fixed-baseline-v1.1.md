## REQ-045 — 既存IAMアクセスキーの完全隔離

Brokerおよびその構成要素は、既存AWS IAM長期アクセスキーを取得、復号、複製、キャッシュ、転送、使用してはならない。

以下の状況でも例外を認めない。

- 初期セットアップ
- 通常のAWS API操作
- 認証情報の更新
- 障害復旧
- バックアップ・リストア
- テスト・デバッグ
- 認証基盤の障害時

Brokerに付与された実行主体の権限では、既存IAMキーの保管領域へアクセスできてはならない。

既存IAMキーを必要とする構成しか成立しない場合、その構成は利用不可と判定する。

## REQ-046 — Bitwardenアクセス権限の最小化

BrokerがBitwarden Secrets Managerを利用する場合、専用Machine Accountと専用Projectを使用する。

以下を必須とする。

1. Broker専用Machine Accountに必要最小限のProjectアクセスのみ付与する。
2. 既存IAM長期アクセスキーを含むProjectへのアクセスを禁止する。
3. Brokerの実行主体にBitwardenの管理者権限・権限割当変更権限を付与しない。
4. Broker専用Projectに既存IAM長期アクセスキーを保存してはならない。
5. Machine AccountのProject割当と権限を管理者が検証できること。
6. 権限が意図せず拡大した場合、安全性を確認できるまでBrokerの秘密情報取得を拒否すること。

既存キーがPassword Managerに保管されている場合、Brokerには当該Vaultを読み取れる認証情報を一切付与しない。

Bitwarden CLIの利用を許可する場合でも、Broker専用Secrets Managerの権限境界を越える操作を許可してはならない。

## REQ-047 — AWS長期アクセスキーへのフォールバック禁止

AWS認証には明示的に許可された認証方式のみ使用する。

OIDC、STSその他の認証方式が失敗した場合、AWS IAM長期アクセスキーへのフォールバックを禁止する。

以下を必須とする。

- 未承認の認証情報ソースを使用しない
- SDKの暗黙的な認証情報探索による長期キー利用を防止する
- 認証失敗時はFail Closedとする
- 別アカウント・別Roleへの自動的な権限拡大を禁止する
- ワークロードIDと実際に使用するAWS Roleの対応関係を検証する

AWS STS一時認証情報を利用すること自体は禁止しない。

## REQ-048 — 対話型利用者の定期的な再認証

対話型利用者に、フィッシング耐性のある本人認証を要求する。

認証セッションには以下を設ける。

- 絶対有効期限
- 無操作有効期限
- 明示的なセッション取消
- 期限満了後の再認証
- 権限取消時のアクセス停止

期限満了後、新たなAWS操作を再認証なしに開始してはならない。

認証期限の延長に、API利用やエージェントによる自動リクエストを無条件に利用してはならない。

書き込み承認においても、承認者の本人性を独立に検証する。

無人型エージェントには、人間の対話型認証セッションを流用させない。独立したサービス主体と認可ポリシーを適用する。

**未確定パラメータ（原文時点）：** 絶対有効期限、無操作期限。

## REQ-049 — 高価値認証情報の漏洩対策

Brokerは、秘密情報を処理するコンポーネントと実行権限を最小化する。

秘密情報について、以下への不要な複製を禁止する。

- AIエージェントのコンテキスト
- MCP応答
- HTTP応答
- 通常ログ・デバッグログ
- 例外情報・スタックトレース
- 環境変数・プロセス間通信
- 永続データストア
- バックアップ
- 監視・テレメトリー

AWS STSの一時認証情報については、AWS API認証に必要な実行時利用を許可する。

ただし、実行環境内の他コンポーネントから取得できないよう権限分離を要求する。

異なる利用者・エージェント・AWSアカウントの一時認証情報を混同・共有してはならない。

一時認証情報が漏洩した場合にも、AWS側の権限・リソース・有効期限によって影響を制限できること。

## AC-021 — 既存IAMキーを使用しないAWS認証

Deno Deploy、Cloudflare Workers、Dockerの各対象環境で、既存IAM長期アクセスキーをBrokerに渡さず、AWS認証を成立させる。

実際のAWSアカウント・Role・認証経路を検証し、利用した認証方式を秘密値なしで記録する。

成立しない環境は未対応として扱い、長期キーによる代替を認めない。

## AC-022 — Bitwarden秘密情報隔離

Broker専用Machine Accountから、許可されたテストSecretは取得できること。

別の保護対象Projectにある模擬IAM長期アクセスキーについては、秘密値の取得が権限によって拒否されること。

実際のIAM長期アクセスキーをテストに使用してはならない。

さらに、Brokerの実行主体からMachine Accountの権限を拡大できないことを確認する。

## AC-023 — フォールバック禁止

以下の障害を注入する。

- OIDC認証失敗
- STSへの接続障害
- 認証情報の期限切れ
- Bitwarden接続障害
- 未承認の認証情報ソースの存在

すべてのケースで、既存IAM長期アクセスキーへのフォールバックが発生しないこと。

許可された認証経路を使用できない場合、AWS操作を拒否すること。

## AC-024 — 利用者セッションの再認証

対話型利用者のセッションについて、以下を検証する。

- 絶対期限満了後のAWS操作拒否
- 無操作期限満了後のAWS操作拒否
- 明示的な取消後のAWS操作拒否
- 再認証後の認可再評価
- 無人エージェントが対話型セッションを流用できないこと

テストは実際の認証基盤を含めて実施する。

## B2-S1 — 後続で確定したREQ-048の値（原文改変でなく追補）

ユーザー確定: 対話型認証の**絶対有効期限8時間、無操作期限15分**。無操作期限を更新できるのは**認証された人間本人の操作のみ**。AIエージェントの自動操作では延長しない。無人型エージェントは独立サービス主体で認証する。

原文の「未確定パラメータ」は確定後の補足B2-S1によって解決する。これは原文の削除・書換えではない。
