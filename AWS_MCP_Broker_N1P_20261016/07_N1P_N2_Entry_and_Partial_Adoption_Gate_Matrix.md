4. Real Owner/Custodian/Design/Security identity/delegation verification receipts,
   actual event IDs/immutable references, approved-at UTC/effective-from UTC,
   trusted signature verification, audit/custody and current revocation status.
5. A different reviewer after adoption, separate from N0/N1/N1-P authors,
   implementers, earlier reviewers and formal approvers. Actual organizational
   independence must be verified; a fresh AI name is not sufficient.
6. Explicit review scope and separate commission, fixed code reference, current
   branch drift comparison if any, unresolved technical findings, disabled
   capability map and evidence limitations. No live feasibility work included.
